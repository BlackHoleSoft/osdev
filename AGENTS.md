# 🤖 AGENTS.md: Спецификация Проекта "WASM-Ядро"

**Кодовое имя проекта:** `Strelka-Wasm-OS`
**Язык разработки:** Rust
**Целевая архитектура:** x86 (64-bit)
**Принцип:** Монолитное ядро с полной изоляцией пользовательского пространства через WebAssembly Virtual Machine (VM).

## 1. 🎯 Общая Цель (Wasm-Ядро)

Создание компактной, безопасной и минималистичной операционной системы, где **все** пользовательские приложения работают в песочнице WebAssembly. Ядро предоставляет только базовые системные сервисы через строго определённый интерфейс (Host Functions).

---

## 2. 🛡️ Агент "CoreBoot": Подсистема Загрузки и Инициализации

**Ответственность:** Начальная загрузка, переход в длинный режим, установка базовой среды.

| Аспект           | Спецификация                                                                                                                                               | Ответственный Агент |
| :--------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------ |
| **Загрузчик**    | GRUB2 (GNU Grand Unified Bootloader)                                                                                                                       | Bootstrapper        |
| **Спецификация** | Multiboot 1 / Multiboot 2. Ядро должно парсить структуру Multiboot Info для получения карты памяти.                                                        | Multiboot-Parser    |
| **Точка Входа**  | `_start` (без `extern "C"`, `#[no_mangle]`). Установка стека.                                                                                              | EntryPoint-Setter   |
| **Режим CPU**    | Переход в 64-битный длинный режим (Long Mode).                                                                                                             | Mode-Switcher       |
| **Память**       | **Flat Memory Model** на уровне ядра. Вся физическая память доступна линейно. Требуется минимальная настройка таблиц страниц (Paging) для длинного режима. | Paging-Minion       |

---

## 3. 🧠 Агент "MemMaster": Подсистема Управления Памятью

**Ответственность:** Предоставление динамического выделения памяти для ядра и Wasm VM.

| Аспект                   | Спецификация                                                                                                                                                                         | Ответственный Агент |
| :----------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------ |
| **Глобальный Аллокатор** | Реализация глобального аллокатора (например, на основе связанного списка, `linked_list_allocator`).                                                                                  | Allocator-Genius    |
| **Инициализация Кучи**   | Выделение фиксированной области памяти из карты, предоставленной Multiboot, для использования в качестве кучи (Heap).                                                                | Heap-Initializer    |
| **Wasm Память**          | VM отвечает за управление памятью внутри _своего_ экземпляра (линейная память Wasm). Ядро предоставляет только кучу для **своих** структур и для начального размещения Wasm-модулей. | Wasm-Memory-Broker  |

---

## 4. 🖨️ Агент "IOGear": Подсистема Ввода/Вывода

**Ответственность:** Базовое взаимодействие с пользователем.

| Аспект         | Спецификация                                                                                                                   | Ответственный Агент |
| :------------- | :----------------------------------------------------------------------------------------------------------------------------- | :------------------ |
| **Вывод**      | **VGA Text Mode Buffer** (`0xb8000`). Прямая запись. Необходим модуль форматирования для обработки строк Rust (`Write` trait). | VGADriver           |
| **Прерывания** | Инициализация **Interrupt Descriptor Table (IDT)** для обработки прерываний.                                                   | IDT-Constructor     |
| **Ввод**       | Базовый драйвер клавиатуры (PS/2), подключенный через PIC/APIC и обработчик прерываний.                                        | KBD-Handler         |
| **Тайминг**    | Настройка программируемого интервального таймера (PIT) для базовой синхронизации (если потребуется для планировщика).          | PIT-Clock           |

---

## 5. 🚀 Агент "WasmHost": Среда Исполнения WebAssembly

**Ответственность:** Запуск, изоляция и взаимодействие Wasm-модулей. **Это сердце проекта.**

| Аспект                      | Спецификация                                                                                                                         | Ответственный Агент  |
| :-------------------------- | :----------------------------------------------------------------------------------------------------------------------------------- | :------------------- |
| **Wasm VM**                 | **`wasmi`** (WebAssembly interpreter) или аналогичный, подходящий для среды `no_std`. Должна поддерживать **Wasm v1 specification**. | Wasm-Runtime-Manager |
| **Загрузка Модуля**         | Загрузка массива байтов Wasm-модуля (может быть вшит в ядро на первом этапе).                                                        | Module-Loader        |
| **Изоляция**                | Каждый Wasm-модуль — это "процесс" или "пользовательское приложение" с собственной изолированной памятью, управляемой VM.            | Sandbox-Enforcer     |
| **Системные Вызовы (Host)** | **Набор функций, импортируемых Wasm-модулями** и _экспортируемых ядром_. Должен быть реализован и связан с VM.                       | Host-Function-Binder |

### 5.1. 📜 Спецификация Host Functions (Системные Вызовы)

Эти функции являются **единственным** способом взаимодействия Wasm-модулей с ядром.

| Название (Wasm Import) | Назначение                                                     | Параметры (Пример)                                                        |
| :--------------------- | :------------------------------------------------------------- | :------------------------------------------------------------------------ |
| `sys_write`            | Вывод данных (например, на консоль VGA).                       | `(fd: u32, ptr: u32, len: u32)` (где `ptr` — это смещение в памяти Wasm). |
| `sys_exit`             | Завершение работы Wasm-модуля.                                 | `(exit_code: i32)`                                                        |
| `sys_alloc`            | Запрос памяти (для Wasm-модуля, если не управляется локально). | `(size: u32) -> u32 (ptr)`                                                |
| `sys_read_char`        | Чтение одного символа с клавиатуры.                            | `() -> u32 (char_code)`                                                   |
| `sys_sleep`            | Приостановка выполнения (требуется PIT-Clock).                 | `(milliseconds: u32)`                                                     |

## 6. 📝 Примечания для Агентов

- **Принцип "Fail Fast":** В случае фатальной ошибки ядра (например, двойной ошибки CPU) необходимо выполнить **бесконечный цикл** и вывести сообщение о панике на консоль. Отладочные сообщения — это священная корова.
- **Использование Крейтов:** Приоритет отдавать крейтам с минимальным количеством зависимостей и поддержкой `no_std`.
- **Тестовый Модуль:** Создать простейший Wasm-модуль на Rust, который вызывает `sys_write` для печати "Hello, Wasm OS!". Это будет ваш **Hello World**.

**Начните с Агента "CoreBoot". Без загрузки ничего не работает.**
